# V3.18 Structured Challenger Ingestion

Status: IMPLEMENTATION IN PROGRESS

V3.18 adds structured, public, read-only challenger observations without weakening Official FPL authority.

## Invariants
- Official FPL remains the native authority.
- Source reachability is distinct from capability-data health.
- A reachable website may legitimately have no accepted structured observation.
- Missing values are never fabricated.
- Only AVAILABLE, non-stale observations are current.
- Last-known-good and stale rows are explicitly labelled and are not current Price Radar inputs.
- Challenger failure is fail-soft.
- Price challenger evidence is context-only and cannot change Official current price, Official price progress, urgency, or decision state.

## Initial structured providers
- LiveFPL public price page
- OneFPL public price page

Both adapters use bounded fetch size and timeout values owned by `config/sources/registry.json`. Parser drift degrades the affected capability to an explicit no-observation state rather than inventing a value.

## Observation contract
`challenger_observation_v2` carries source/capability, subject, value, source URL, fetched/observed timestamps, provenance, parser version, TTL, stale state, confidence and error/status metadata.

Cross-source price comparison compares direction only (`RISE`, `FALL`, `STABLE`) because provider-specific percentages can have different semantics. Agreement/disagreement is therefore explicit without pretending the raw percentages are directly interchangeable.

## Runtime flow
1. `source_layer` fetches/probes registered sources once.
2. Fresh observations are normalized and reconciled with the prior persisted observation store.
3. `challenger_observations.json` is promoted as a versioned runtime artifact.
4. The price service consumes that artifact after Official Price Radar generation and attaches context only to uniquely matched Official player rows.
5. Reports render source reachability and structured-data availability separately.

Release metadata remains on the current production version until full V3.18 unit/integration acceptance passes.

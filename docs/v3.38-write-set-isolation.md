# V3.38 Write-set Isolation

V3.38 isolates the MODEL and MARKET execution domains so they can run concurrently without sharing a mutable `latest.json` workspace.

Each domain receives a private data workspace seeded only from declared service inputs/artifacts plus `latest.json` and incremental reuse state. Both domains execute concurrently. No canonical output is promoted until both domain processes complete successfully.

Fan-in is deterministic and contract-driven:
- only declared service artifacts are copied back;
- only declared `latest_keys` and `latest_file_keys` are merged into canonical `latest.json`;
- incremental reuse fingerprints are merged only for capabilities owned by the promoted domain;
- MODEL is promoted before MARKET for deterministic ordering, although their declared write sets are required to remain disjoint.

This changes execution mechanics only. Capability ownership, football formulas, DSS logic, source authority, Gate0, watchlist, reporting, and artifact validation remain unchanged.
